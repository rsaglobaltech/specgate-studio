What the brief does not say, chosen so the scenarios can be tested. Each is to
confirm by the person reviewing the draft.

|---|---|---|---|---|

| A3 | A row is a gap when its scenario lacks a feature file, a test that names it, or code; "without a test" is the subset that lacks a test; "waiting for an answer" is the rows whose requirement an open question blocks (`specgate questions --json`, `blocks`) or that is in Needs Clarification | REQ-121, REQ-122 | The brief names the filters, not what each keeps | confirmed |
| A4 | The status shown is the requirement's status from its trace (Draft, Approved, Implemented, Verified, Released, Deprecated, Needs Clarification) | REQ-121, SCN-361 | specgate's statuses; the brief says "status" | confirmed |
| A5 | The rows come from specgate's per-scenario rows. **specgate 0.33.2 does not give them**: `specgate matrix --json` (and the API's `matrix()`) returns only `rows: <count>`, and `specgate report --format json` gives one row per requirement. As answered in Q2, the studio asks specgate for `rows[]` in both the CLI (`specgate matrix --json`) and the API (`matrix()`) — one per scenario: `requirement`, `scenario`, `feature`, `tests[]`, `code[]`, `status`, `gaps[]` — expected in specgate 0.35.0, and builds against that; there is no interim per-requirement view. REQ-121 and REQ-122 are built once specgate 0.35.0 is out | REQ-121, REQ-122 | The studio never parses `traceability.md` (ADR-0003); Q2 | confirmed |
| A6 | The skeleton goes where the project keeps tests for that module, named after the requirement (`test/pagos/REQ-020.test.ts` in the example), in the project's test style, with one step per GIVEN, WHEN and THEN and a failing placeholder where the assertions go; it names REQ-020 and SCN-020b so specgate links it. The studio writes it from the scenario alone: no agent runs and nothing is spent | REQ-123, SCN-366, SCN-367 | specgate links a test by the ids it mentions; Q1 | confirmed |
| A7 | Confirming writes only that test file; it never commits, never runs the tests and never marks the requirement; the next step it names is `specgate apply REQ-020` | REQ-123, SCN-367 | "nothing is written without confirmation"; apply is the gate's job | confirmed |
| A8 | "Fix" and "Ask the agent" have a "?" and their notices (written, or nothing written) in English and Spanish in the help catalog, and the tests fail without them (draft-help REQ-061 … REQ-065); filters and rows are read-only and need no "?" (draft-help A8) | REQ-123, SCN-367, SCN-368, SCN-369 | The studio explains itself | confirmed |
