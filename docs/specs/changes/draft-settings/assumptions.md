# Assumptions — draft-settings

What the brief does not say, chosen so the scenarios can be tested. Each is to
confirm by the person reviewing the draft.

| # | Assumption | Used in | Why | Status |
|---|---|---|---|---|
| A1 | The example is sprich: its test command `npm test` before the brief's `pnpm test`; its profiles `claude-sonnet` and `claude-opus` in `.harness/profiles.yaml`; its `alm.config.yaml` with the provider jira and `token_env: JIRA_API_TOKEN`; its agent guards on; its quality checks at the level basic | REQ-141 … REQ-143, SCN-421 … SCN-428 | sprich's own files; the ALM values are an example | to confirm |
| A2 | Project scope is what specgate keeps in the project (`harness.config.yaml`, `.specgate/config.json`, `.harness/profiles.yaml`, `alm.config.yaml`); User scope is the studio's own settings file, `settings.json` in the user's configuration folder: `~/Library/Application Support/specgate-studio/` on macOS, `%APPDATA%\specgate-studio\` on Windows, `$XDG_CONFIG_HOME/specgate-studio/` (default `~/.config/specgate-studio/`) on Linux — the same file for the desktop app and `specgate-studio serve` | REQ-141, SCN-422 | Cross-platform; the studio stores nothing else (runtime-environments) | to confirm |
| A3 | Scope per section: Agents and profiles, Preferences, Agent guards, Quality and ALM are project settings; Editor, Terminal, Shortcuts and Appearance are user settings; the studio's language and theme (draft-workbench REQ-034) live in Appearance; specgate's `language` (the language of generated prose) is a project preference | REQ-141, REQ-143 | The brief lists the sections, not their scope | to confirm |
| A4 | Search matches a setting's name, its description and its specgate key (`test_cmd`), in the studio's language (English or Spanish), and keeps the scope it is in | REQ-141, SCN-421 | A search box in a settings editor, as VS Code's | to confirm |
| A5 | Saving a project setting runs `specgate config set <key> <value>` through `SpecgatePort` (arguments as an array, no shell, one write at a time: REQ-006, REQ-007); a value specgate refuses shows its finding code and fix: the agent `claude -p` is refused with `config_value_invalid` and the fix `specgate config set agent "claude -p < {prompt_file}"` | REQ-142, SCN-423, SCN-424 | specgate owns its files | to confirm |
| A6 | **specgate 0.33.2 is missing, and 0.35.0 is expected to add**: where each config key lives, and a catalog of keys. Today `config set --json` and `config get --json` answer `{config: {key: value}}` without the file (prose only: "Stored in .specgate/config.json (test_cmd in harness.config.yaml)"), and `config list --json` lists only the keys set. The studio needs, per key, its `file`, allowed `values` and `describe` (a `specgate config schema --json`, or those fields in `config list --json`; the name is specgate's). REQ-142 and REQ-143 read the command and the file from it, never from prose | REQ-142, REQ-143 | The studio says where from JSON, never from prose | to confirm |
| A7 | **specgate 0.33.2 is missing, and 0.35.0 is expected to add** `config set` keys for agent profiles (`.harness/profiles.yaml`), quality checks (`quality:` in harness.config.yaml) and ALM (`alm.config.yaml`); today it sets `profile`, `language`, `pet`, `agent_guard`, `test_cmd`, `arch_cmd` and `agent` only. The key names are specgate's to choose; the levels basic and strict are those of `specgate quality init --level basic|strict` | REQ-143, SCN-425, SCN-426, SCN-428 | What `specgate config set --help` lists | to confirm |
| A8 | A credential is never stored by the studio and never shown: ALM shows the name of the variable in `token_env` and whether it is set in the environment the host was started with | REQ-143, SCN-426 | runtime-environments rule 1 | to confirm |
| A9 | Saving a setting has a "?" and a notice (the command run, the file written, the next step) in English and Spanish in the help catalog (draft-help REQ-061 … REQ-065); the next step after the test command is `specgate check` | REQ-141, REQ-142, SCN-422, SCN-423, SCN-427, SCN-428 | The studio explains itself | to confirm |
| A10 | Shortcuts start from the workbench's set (draft-workbench REQ-032) and can be rebound per user; Editor (font size, tab size, word wrap) and Terminal (shell, font size, scrollback) are user settings the studio itself keeps | REQ-143 | The workbench and terminal capabilities | to confirm |
| A11 | The desktop app and the browser show the same Settings (ADR-0001): the core host reads and writes both scopes | REQ-141 … REQ-143 | The core host's capability | to confirm |
| A12 | Agents and profiles, Quality and ALM ship with the specgate release that adds their `config set` keys (expected 0.35.0); they are not shown read-only before it, and the studio never edits `.harness/profiles.yaml`, `harness.config.yaml` or `alm.config.yaml` itself. The other six sections can ship first | REQ-143 | Q1: ask specgate for the keys first | to confirm |
