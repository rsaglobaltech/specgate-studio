# Design: specgate-1-4-setup

> Owner: architect — how the system meets the Discover. Name each acceptance
> criterion (AC-1, AC-2…) where it is answered.

## Modules

- `packages/core/src/domain/setup.ts`: `readiness()` gains `stack` and `testing`, with `TBD` read as to decide.
- `packages/core/src/domain/home.ts`: the next step "Decide the stack" while either is `TBD`, before Build.
- `packages/core/src/domain/settings.ts`: the words for `stack` and `testing`, under Preferences.
- `packages/core/src/domain/build.ts`: `BASELINE` becomes a function of the project. It is the requirement tagged in `features/adoption/baseline.feature` and titled "Preserve existing behaviour". It falls back to REQ-000 for a project adopted before specgate 1.4.
- `apps/ui`: the readiness list's two new rows, and the line under Home's counters.

## Mechanisms

- AC-1 — REQ-228. `config list --json` gives `stack` and `testing` from `AGENTS.md` (specgate 1.4.2). A save runs `config set stack|testing "<value>"` through the commands the readiness list already runs.
- AC-2 — REQ-229. Settings already lists every key `config keys` gives; these two only lack words.
- AC-3 — REQ-230 and MODIFIED REQ-101. The baseline is told by its feature file and title. `status --json` does not tell it apart: specgate 1.4.1 changed only `status`'s text.
- AC-4 — REQ-230. "Build and test the project" is not "Preserve existing behaviour", so it is counted.

## Channels

No new JSON-RPC method: `home.get` and the setup's readiness answer more.

## Decisions

- The adoption preview keeps the list `ADOPT_FILES`, which already names `.specgate/gate.yaml`. Reading `adopt --dry-run` was considered and rejected: it has no `--json`, and parsing specgate's prose breaks on its next wording. The ask goes to specgate.
- Part 5 of the issue — the CI workflow generated by specgate 0.31, and `apply`'s two findings — is repository upkeep, outside this change.
