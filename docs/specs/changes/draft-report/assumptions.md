# Assumptions — draft-report

What the brief does not say, chosen so the scenarios can be tested. Each is to
confirm by the person reviewing the draft.

| # | Assumption | Used in | Why | Status |
|---|---|---|---|---|
| A1 | The example is sprich's module `pagos`: 6 requirements, 2 Implemented, coverage 74 % (the brief's values); its report file is `sprich-report-pagos.html`, saved to the folder Downloads; the profile `claude-sonnet` is sprich's (`.harness/profiles.yaml`) | REQ-131, REQ-133, SCN-391, SCN-395, SCN-397 | The brief's example; the file name is the project and the module | to confirm |
| A2 | "Built" is a requirement Implemented, Verified or Released; "scenarios proven" is a scenario a test names and the last gate passed | REQ-131 | The brief names the measures, not their definitions | to confirm |
| A3 | A module is a module of the brief: an open change from the brief, or the capability it was archived into | REQ-131, SCN-391 | Report is for the client, who knows the modules | to confirm |
| A4 | The numbers come from specgate's JSON: built and total from `specgate report --format json` (`total`, `implemented`); diff coverage, mutation score, estimated cost and time from `specgate harness report --json` (`report.quality.coverage`, `report.quality.mutation`, `report.estimatedCost.total`, `report.totalMs`). **specgate 0.33.2 is missing, and 0.35.0 is expected to add**: a module filter on `report` and `harness report`, and the module in `status --json`; per-scenario rows for "scenarios proven" (`matrix --json` `rows[]`, draft-traceability A5); the cost measured from the agent's tokens in `harness report --json`. REQ-131 is built against specgate 0.35.0 | REQ-131 | The studio never parses prose (ADR-0003) | to confirm |
| A5 | A measure specgate has not taken (`null` in its JSON) shows as not measured with the command that measures it; for coverage and mutation that is `specgate quality init --level strict` | REQ-131, SCN-392 | specgate's quality checks measure both | to confirm |
| A6 | The gate's stages and their names are specgate's: specification (`validate --strict`), architecture (`arch_cmd`), tests (`test_cmd`) and each quality check; the codes and fixes are specgate's own (`check_tests_failed`, "Make `npm test` pass, then run `specgate check` again.") | REQ-132, SCN-393 | `specgate check --json` | to confirm |
| A7 | **specgate 0.33.2 is missing, and 0.35.0 is expected to add**: `stages[]` on every `specgate check --json` answer, passed or failed — `stage`, `command`, `result` (passed, failed, not_configured, not_run) and `findings[]` with their fix. Today a failing `check --json` returns only the failing stage's code (`check_validate_failed`, `check_arch_failed`, `check_tests_failed`, `check_quality_failed`). REQ-132 is built against specgate 0.35.0 | REQ-132 | Without it, the stages before a failure cannot be shown from JSON | to confirm |
| A8 | "The last gate" is the last gate specgate records for the project, with when it ran — a last-gate result specgate 0.35.0 is expected to add (its command and field are specgate's to name; `specgate check --last --json` is this draft's guess). With it, Report shows the last gate after a restart without running one; with none recorded, it says no gate has run yet | REQ-132, SCN-394, SCN-398 | The studio keeps no data beyond the project's files and the user's settings (runtime-environments) | to confirm |
| A9 | The downloaded page is the studio's own report, rendered from the same data and in the studio's language (English or Spanish); not `specgate report --format html`, which has no cost, mutation score or gate by stage | REQ-133, SCN-395 | The report is for the client | to confirm |
| A10 | On the desktop, Download asks where to save with the system's dialog; in the browser it is a browser download. Print uses the webview's or the browser's print dialog, whose "Save as PDF" is the system's; the studio writes no PDF itself | REQ-133, SCN-395, SCN-396 | Same on macOS, Windows and Linux without a PDF library | to confirm |
| A11 | Download and Print have a "?" and Download its notice (the file written, the next step) in English and Spanish in the help catalog (draft-help REQ-061 … REQ-065); Print writes nothing; opening Report runs nothing | REQ-133 | The studio explains itself | to confirm |
| A12 | The desktop app and the browser show the same Report (the core host serves both, ADR-0001) | REQ-131 … REQ-133 | The core host's capability | to confirm |
| A13 | Coverage shows two labelled figures: the harness's diff coverage per requirement (`report.quality.coverage`, a mean over a module's requirements), and the project's line coverage when a run measured it, else "not measured". **The project's line coverage is not in specgate's JSON today, and is not among what specgate 0.35.0 is expected to add**: it needs a field such as `coverage.lines` in `harness report --json` or `check --json`, and a check that measures it — until then it shows as not measured | REQ-131, SCN-391 | Q1: both, labelled | to confirm |
| A14 | Cost is the one measured from the agent's tokens when specgate has it (expected in specgate 0.35.0's `harness report --json`), labelled measured; otherwise the estimate declared per agent profile (`report.estimatedCost`), labelled estimated, naming the profile | REQ-131, SCN-391, SCN-397 | Q2: both, the measured one when it exists | to confirm |
